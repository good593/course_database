# 2차시. 키와 기본 명령어

## 학습 목표

- 일관된 규칙으로 Redis 키를 설계할 수 있습니다.
- 키의 존재 여부, 자료형, 삭제 여부를 확인할 수 있습니다.
- `KEYS`와 `SCAN`의 차이를 설명할 수 있습니다.

## 1. 키 이름 설계

Redis에는 테이블이 없으므로 키 이름이 데이터의 의미를 전달해야 합니다.
이 강의에서는 다음 규칙을 사용합니다.

```text
서비스:대상:식별자[:속성]
```

```text
shop:product:1001
shop:product:1001:views
community:user:7:session
```

### 좋은 키의 조건

- 의미가 분명하고 충돌하지 않습니다.
- 너무 짧거나 지나치게 길지 않습니다.
- 같은 종류의 키는 같은 패턴을 사용합니다.
- 개인정보를 키 이름에 직접 넣지 않습니다.

## 2. 기본 저장과 조회

```redis
SET shop:product:1001 "무선 키보드"
GET shop:product:1001
EXISTS shop:product:1001
TYPE shop:product:1001
DEL shop:product:1001
EXISTS shop:product:1001
```

- `EXISTS key`: 키가 있으면 `1`, 없으면 `0`
- `TYPE key`: 키에 저장된 자료형 확인
- `DEL key [key ...]`: 하나 이상의 키를 즉시 삭제

큰 값이나 많은 키를 삭제할 때는 메모리 해제를 비동기로 처리하는 `UNLINK`도
사용할 수 있습니다.

```redis
UNLINK temporary:large-data
```

## 3. SET 옵션

```redis
SET signup:email:user@example.com 1 NX
SET shop:product:1001 "새 이름" XX
SET auth:code:1001 482913 EX 180
```

- `NX`: 키가 없을 때만 저장
- `XX`: 키가 있을 때만 저장
- `EX 초`: 저장과 동시에 초 단위 만료 시간 설정
- `PX 밀리초`: 저장과 동시에 밀리초 단위 만료 시간 설정

조건을 만족하지 못한 `SET`은 `(nil)`을 반환합니다. `NX`는 간단한 중복 방지에
유용하지만, 복잡한 분산 잠금은 만료와 소유권 확인까지 별도로 설계해야 합니다.

## 4. 키 이름 변경

```redis
SET old:key value
RENAME old:key new:key
GET new:key
```

`RENAME`은 대상 키가 이미 있으면 덮어씁니다. 덮어쓰기를 막으려면
`RENAMENX`를 사용합니다.

## 5. 키 탐색: KEYS와 SCAN

```redis
KEYS shop:product:*
SCAN 0 MATCH shop:product:* COUNT 10
```

`KEYS`는 조건에 맞는 키를 한 번에 모두 찾습니다. 데이터가 많은 서버에서는
처리 중 다른 요청을 지연시킬 수 있으므로 수업용 작은 데이터에서만 사용합니다.

`SCAN`은 커서를 사용하여 키를 여러 번에 나누어 탐색합니다.

```redis
SCAN 0 MATCH shop:* COUNT 100
```

반환된 첫 번째 값이 다음 커서입니다. 그 커서로 다시 `SCAN`하며, 반환 커서가
`0`이 되면 탐색이 끝납니다. `COUNT`는 한 번에 확인할 양에 대한 힌트이며 정확한
반환 개수를 보장하지 않습니다. 탐색 중 같은 키가 중복으로 보일 수도 있습니다.

## 실습. 상품 키 관리

다음 상품 세 개를 저장합니다.

```redis
MSET shop:product:1001 "키보드" shop:product:1002 "마우스" shop:product:1003 "모니터"
MGET shop:product:1001 shop:product:1002 shop:product:1003
TYPE shop:product:1001
EXISTS shop:product:9999
SCAN 0 MATCH shop:product:* COUNT 10
DEL shop:product:1001 shop:product:1002 shop:product:1003
```

### 도전 과제

`NX`를 이용해 같은 이메일이 두 번 가입하지 못하도록 키를 설계하고 결과를
확인합니다.

## 자주 발생하는 오류

```redis
SET sample:key text
LPUSH sample:key item
```

한 키는 한 가지 자료형으로 사용합니다. String 키에 List 명령을 실행하면
`WRONGTYPE` 오류가 발생합니다. `TYPE sample:key`로 먼저 확인할 수 있습니다.

## 확인 문제

1. `NX`와 `XX`의 차이는 무엇인가요?
2. 운영 환경에서 `KEYS *` 사용을 피해야 하는 이유는 무엇인가요?
3. `SCAN` 탐색이 끝났음을 어떻게 알 수 있나요?
4. 키 이름에 콜론을 사용하는 목적은 무엇인가요?

## 정리

- 키 이름은 Redis 데이터 모델의 일부입니다.
- `EXISTS`, `TYPE`, `DEL`로 키의 상태를 관리합니다.
- 운영 환경의 점진적 키 탐색에는 `SCAN`을 사용합니다.
